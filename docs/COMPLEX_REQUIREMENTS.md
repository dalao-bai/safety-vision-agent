# 复杂需求扩展构想

日期：2026-06-03

本文档记录 `safety-vision-agent` 后续可以扩展的复杂需求。当前阶段只做需求沉淀，不直接实现。

## 1. 总体方向

项目不应停留在“上传图片、模型回答”的识图工具层面，而应逐步升级为：

```text
识别隐患
-> 解释依据
-> 主动追问
-> 生成整改建议
-> 跟踪整改闭环
-> 人工复核
-> 反哺微调数据
```

核心目标是让 Agent 更像“施工安全隐患识别专家”，而不是一个单次推理接口。

## 2. 优先级最高的三类复杂需求

### 2.1 隐患整改闭环

需求描述：

Agent 不只是识别隐患，还要把隐患转成整改任务，并支持整改后复查。

典型流程：

```text
发现隐患
-> 生成整改建议
-> 生成整改任务
-> 设置责任人和期限
-> 上传整改后照片
-> Agent 对比复查
-> 判断是否整改完成
```

核心能力：

- 生成整改任务。
- 支持整改前后图片对比。
- 判断原隐患是否消除。
- 记录整改状态。
- 生成整改闭环报告。

价值：

- 从识别系统升级为安全管理系统。
- 更接近真实施工现场检查流程。
- 适合项目展示和后续产品化。

### 2.2 主动追问与 uncertain 复核机制

需求描述：

当图像证据不足时，Agent 不强行判断，而是主动说明缺少什么证据，并引导用户补充。

典型回复：

```text
该楼层临边区域被材料遮挡，无法确认防护是否连续。
请补充一张临边近景图，或提供现场验收信息。
```

支持的证据不足类型：

- 关键防护构件不可见或被遮挡。
- 图像不足以判断尺度、强度或固定状态。
- 判断依赖工程阶段、验收记录或现场复核资料。

核心能力：

- 将 `uncertain` 结果转成可执行追问。
- 根据缺失证据生成补充拍摄建议。
- 支持用户上传补充图片后重新判断。
- 将前后多张图片合并为一个判断链。

价值：

- 与当前微调论文中的 `uncertain` 机制高度一致。
- 可以显著降低模型幻觉和过度判断。
- 体现专家系统的谨慎性。

### 2.3 人工复核学习闭环

需求描述：

人工可以修正 Agent 的判断，系统记录修正前后的差异，用于后续数据集扩充和微调。

典型流程：

```text
Agent 输出隐患判断
-> 人工 accept / revise / reject
-> 系统记录原始判断和人工修正
-> 标记错误类型
-> 生成可加入训练集的样本
-> 后续用于 SFT / Hard Negative / DPO
```

核心能力：

- 支持人工确认、修改、拒绝结果。
- 记录模型错误原因。
- 将复核结果转成训练样本候选。
- 生成 hard negative 或 DPO 数据候选。
- 形成数据闭环。

价值：

- 连接 Agent 工程和微调研究主线。
- 支持模型持续改进。
- 适合论文中体现“人机协同标注”和“反幻觉训练”。

## 3. 其他可扩展复杂需求

### 3.1 法规/规范 RAG 检索

将四口五临边规则库扩展为更完整的法规知识库。

可检索内容：

- 四口五临边规则块。
- 施工安全规范条文。
- 检查表。
- 整改模板。
- 安全技术交底内容。

目标：

- 用户问“依据是什么”时，Agent 能引用规则来源。
- 用户问“为什么这样整改”时，Agent 能解释条文含义。

### 3.2 多专家协作 Agent

将单 Agent 拆成多个专家角色：

```text
视觉隐患专家：调用微调 VLM
PPE 专家：检测安全帽、安全带、反光衣
规则专家：检索规范依据
整改专家：生成整改建议
质检专家：检查结论是否有证据支撑
报告专家：生成最终报告
```

目标：

- 提升系统可解释性。
- 便于扩展不同安全检查方向。
- 避免一个 Agent 同时承担所有职责。

### 3.3 证据一致性校验

Agent 自检各工具输出是否矛盾。

示例：

```text
VLM 判断 confirmed_hazard，但视觉证据描述空泛。
规则依据和隐患类型不匹配。
YOLO 检测到人员靠近临边，但 VLM 未提及人员暴露风险。
```

目标：

- 标记低可信判断。
- 触发人工复核。
- 降低幻觉输出。

### 3.4 批量巡检模式

支持一次上传多张图片或一个文件夹。

输出：

- 批量隐患清单。
- 风险类型统计。
- 高风险图片排序。
- 项目级日报/周报。

### 3.5 风险等级评分

为每个隐患生成风险等级：

```text
低风险
中风险
高风险
重大风险
```

评分因素：

- 隐患类型。
- 防护缺失程度。
- 是否有人靠近。
- 是否涉及临边/洞口。
- 证据充分性。
- 多风险叠加情况。

### 3.6 危险区域交互标注

用户可以在图片上框选区域并提问：

```text
分析红框内是否有隐患。
这个区域是基坑边，判断是否需要防护。
这个区域禁止人员进入，检查是否有人进入。
```

目标：

- 支持局部分析。
- 支持用户指定关注区域。
- 提升多轮对话的可控性。

### 3.7 多格式报告

支持不同报告模板：

- 简版现场报告。
- 正式整改通知单。
- 隐患台账。
- 复查报告。
- 论文实验分析报告。

### 3.8 项目级长期记忆

Agent 记录某个项目长期风险画像：

```text
本项目楼层临边防护缺失出现频率较高。
本周未戴安全帽问题较上周增加。
电梯井口防护门问题多次重复出现。
```

目标：

- 从单次识别升级为长期安全助手。
- 支持趋势分析和管理建议。

## 4. 推荐实施顺序

建议后续按以下顺序推进：

```text
1. 主动追问与 uncertain 复核机制
2. 人工复核学习闭环
3. 隐患整改闭环
4. 证据一致性校验
5. 法规/规范 RAG 检索
6. 批量巡检模式
7. 多专家协作 Agent
8. 项目级长期记忆
```

原因：

- `uncertain` 复核机制最贴合当前微调研究主线。
- 人工复核学习闭环可以反哺训练数据。
- 整改闭环能提升项目应用价值。
- 证据一致性校验能降低幻觉风险。

## 5. 当前不建议优先做的需求

暂不建议第一阶段优先做：

- VLM 后台实时视频逐帧巡检。
- 多摄像头实时监控平台。
- 复杂权限系统。
- 全量法规知识库自动问答。
- 大规模在线训练或强化学习。

这些需求复杂度高，容易偏离当前“基于微调 VLM 的多轮隐患识别专家 Agent”主线。
